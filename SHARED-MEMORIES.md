# Shared Wedding Memories

Run `supabase/shared-memories.sql` after the existing wedding-project, private file-storage and storage-recovery migrations. The downloadable copy is `C:/Users/ayeni/Downloads/cobridey-shared-memories.sql`. This adds native shared albums, contribution records, review history and signed-in album invitations. It preserves existing private memory collections and their account cloud saves; nothing is automatically published or imported from private albums.

Open **Wedding Memories → Shared albums & guest uploads**. Wedding managers can create albums and associate a celebration. Only the wedding owner can open/close guest uploads, share approved media, archive albums, approve/hide/restore contributions or rotate the guest link. Albums start private with guest uploads off. Copying a link is a user action; no invitations or emails are sent by this implementation.

Guests open the album link and sign in/create an account. Its capability authorizes only that album, not the bridal workspace or unrelated wedding records. Claim generations are checked on every read/write. Revoking guest access rotates the link and invalidates earlier claims; guests need the new link to return. Closing uploads prevents submissions while approved shared viewing can remain open. Archiving closes both. Guest links are independent of RSVP household links and can be forwarded; rotate the album link to revoke that access.

Contributions accept verified private image/video uploads up to the existing 20 MB per-file limit and account file allowance. The existing upload helper reserves quota, uploads immutable content and verifies its hash. The server checks ownership, stored content type/size, album permission and cleanup state before creating a media record. New or replaced content always enters Pending review and resets previous approval. Exact request IDs make retries idempotent; revisions reject conflicting edits/reviews. New submissions are capped at 100 per contributor per hour and 10,000 records per album. Album creation is capped at 500 per wedding. Gallery pages return 100 records plus a look-ahead, using timestamp/ID cursors to prevent tied-timestamp omissions.

Managers can review album media. Guests see their own submissions and only Approved items when guest viewing is enabled; other guests' pending/hidden items are excluded by server permissions and Storage RLS. Private account files remain private unless deliberately submitted to an album. Native gallery media URLs last five minutes; previously issued URLs can work until expiry after access revocation. No public bucket or service-role credential is introduced. Uploaders retain access to their own original account files. Linked files and historical versions are protected from unused-file cleanup, including archived albums. Archiving preserves data and is not permanent deletion.

Tests cover role and raw-table isolation, default privacy, guest claims, link rotation, upload closure, owner-only approval, replacement resetting approval, shared file reads, cleanup protection, revision conflicts, exact retries, pagination with tied timestamps, mobile forms, retry after an interrupted upload save and guest-only controls. The existing authenticated portal and private memory presentation remain intact. No real guest or external recipient was contacted; live multi-device testing remains deferred by the user.

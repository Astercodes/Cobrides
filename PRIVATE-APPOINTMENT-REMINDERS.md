# Private appointment reminders

Run `supabase/private-appointment-reminders.sql` after private-appointments.sql and the existing shopping/planning notification and email migrations. The downloadable copy is `C:/Users/ayeni/Downloads/cobridey-private-appointment-reminders.sql`. Existing appointment records, notification preferences, financial records and email secrets are retained. No provider booking is made.

Beauty & Self-care → appointment → Appointment details → Reminders offers one lead time: 15/30 minutes, 1/3 hours, 1/2 days or 1 week. In-app and email are separate explicit opt-ins, off by default. Email is disabled in the demonstration workspace. Confirmed future appointments with current reviewed source details are required. Users can turn reminder channels off even when a source has changed. Conflicting settings from another device are rejected; interrupted writes use the exact original request ID.

Private notices have no shared-project association. Owner-only RPCs and inbox row policies enforce ownership; explicit owner lookup helpers used by cron have no client grants. Notification and email copy is generic and excludes appointment title, location, provider, reference and private notes. Opening a reminder rechecks its current state and account before loading the selected private appointment.

The server calculates due times from the appointment's saved UTC instant and selected lead time. Changing an appointment/source immediately hides obsolete notices and blocks queued sends; after review and confirmation the new appointment revision uses the existing reminder settings. Cancellation, completion, archival, expired start times, opt-out and changed/invalid sources suppress dispatch. An already submitted message cannot be withdrawn. Deduplication keys include the appointment and preference versions. Shared planning digest counts explicitly exclude these private reminders.

The existing paced Resend worker processes private email jobs as well as daily shared summaries. The same daily/monthly allowance, pause handling, retry window, provider idempotency keys, signed webhooks and bounce/complaint suppression apply. Private jobs do not consume the once-per-day shared digest slot or advance its watermark. Private emails are independent of the daily-summary switch. No email is sent by applying this migration unless a user has explicitly enabled a future private appointment reminder. Cron checks each minute when pg_cron is installed; email queue/provider delays can affect arrival time. In-app checks also run when opening the notification inbox.

Appointment timezone/DST and scheduling tests remain passing. No live recipient email or real-account multi-device test was performed; these remain deferred by the user.

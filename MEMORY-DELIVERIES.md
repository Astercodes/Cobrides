# Professional deliveries in Wedding Memories

Run `supabase/memory-deliveries.sql` after shared-memories.sql and vendor-deliverables.sql. Downloadable activation file: `C:/Users/ayeni/Downloads/cobridey-memory-deliveries.sql`. No new provider keys are needed. Existing private memories, albums, vendor decisions and files remain intact.

In Shared albums, **Professional deliveries** lists accessible photo/video submissions for the current wedding. Review delivery opens the existing vendor coordination and submission-review workflow. Its existing reviewer permissions and immutable version decisions are retained. Short MP4/WebM video delivery uploads are added to the existing private vendor bucket and form; the current 20 MB per-file and account storage limits still apply.

Only the wedding owner can add a current, Approved media submission to an album in the same wedding. The server checks current project/album access, both expected revisions, latest source version, vendor/work state, file metadata and cleanup status. Contracts, PDFs and other non-media documents cannot be imported. Review notes and commercial details are never copied into captions or returned by the memory-delivery browser.

Adding a delivery creates a Pending review memory that references the original immutable file and its source version. It does not copy/upload the bytes, change the vendor review, complete a work item or record a payment. Album approval remains a separate owner action. New vendor versions do not automatically replace a memory already selected for an album. One source submission can appear once in a particular album; exact retries return the original result, while repeated fresh selections are rejected with an explanatory error.

Album Storage policies extend access only to selected memories under existing album permissions. Pending vendor imports are hidden from other guests; approved ones become readable only when guest viewing is enabled. Signed album URLs remain short-lived. Cleanup checks protect both current references and historical versions in either private bucket. Replacing an imported memory with an owner-uploaded file resets provenance and approval, and returns to the normal private-memory bucket. Original file storage remains charged against its uploader's existing allowance; no duplicate copy is created.

Tests cover original album/guest protections, actual vendor submission/review functions, Pending/superseded rejection, owner-only import, same-wedding validation, PDF exclusion, duplicate retries, independent album approval, guest file access, preservation of the selected source version and cleanup history, replacement reset and mobile interrupted-save retries. No real vendor/guest account or live email was used. Real-account multi-device testing remains deferred by the user.

# Documents — Bridal Document Template Library

Entry: bride portal → Documents, beside Central. This replaces the old basic Documents view rather than adding a duplicate module. Accepted collaborators open Documents from the shared wedding workspace. Platform administrators use Admin → Document template administration, independently of any wedding project.

The official starting collection has 52 distinct templates across the twelve requested categories, including the supplied planning, finance, vendor, guest, experience, fashion, relationship, spiritual, travel, home and administration titles. They are editable document snapshots, not replacement ledgers, task boards, guest lists or other planning systems. Existing private file records can be explicitly brought into the new library once; their original objects and records are retained. An origin key prevents repeated import from duplicating a document.

Users can start blank, upload files, choose a template or duplicate a document. Personalization is opt-in per field: saved names, dates, venue, budget, counts, styling, vendor details, responsibilities and available schedule references are shown for review before insertion. Required template fields are checked both in the form and server-side. Editing a document never changes its source planning records.

The writing canvas supports headings, fonts, colors, emphasis, alignment, lists, editable tables, extra rows, checkboxes, links and uploaded images. Metadata and insert/layout controls are tucked away; mobile tables scroll inside the paper instead of squeezing their text. Draft autosaves serialize changes with revision checks and exact retries. Conflicts retain the editor text and expose retry/reload controls; a current draft can still be previewed and exported for recovery. Word exports contain editable tables and rich text; PDF uses a print-ready A4 preview and the browser's Print/Save as PDF interface. No electronic signature is generated. Signed status records a selected uploaded signed copy and a signature date.

Folders support subfolders, event organization, tags, favorites and search. Documents can link to accessible tasks, vendors and payment records. Comments and suggestions require Edit/Review permission; View is read-only. Only a creator can share, revoke, request approval, change workflow, delete or restore history. Review approvals bind to the requested content revision; new review requests and content changes invalidate old approval decisions. Version restoration creates a new draft rather than rewriting history.

Documents and personal templates are private by default, including legal/identity and journal/counseling material. Administrators can manage official templates, categories, regional variations, versions, required/optional fields, examples, free/premium access, featured status, retirement, usage counts and feedback; they cannot inspect private documents or another user's personal templates. Admin status and paid-template access are checked in PostgreSQL. Signed-in clients have no raw document table access. HTML is allowlisted whenever inserted into the UI or exported. Uploaded files use private storage and permission checks; short signed URLs are not stored in document content. Revocation cannot recall copies already downloaded or intentionally duplicated.

Recovery lasts thirty days. A creator can recover or permanently delete a document; permanent deletion removes its content, comments, reviews, versions and old request payloads. Expired recovery entries are purged nightly when Supabase Cron is available; cb_purge_expired_documents is the server-only maintenance function otherwise. Files still referenced by another record remain protected. Recoverable document versions protect their attachments for thirty days. The editor shows the latest thirty saved versions; restoring an old version fails clearly if an attachment is no longer available.

Updates use the existing permission-checked notification bell and opt-in email-summary settings. Shared-change notices are coalesced into ten-minute windows to avoid an autosave notification flood. Private reminders go only to the creator who enabled them, using recorded deadline/expiry dates and existing notification categories. Notification text is generic; titles and sensitive document contents remain inside the authenticated library.

Activation: run all of Downloads/cobridey-documents.sql in Supabase. It combines document-library.sql, document-notifications.sql, document-admin.sql and document-retention.sql in dependency order. All are additive and rerunnable; official seeds never overwrite administrator edits. Existing account, project access, storage, notification, vendor and financial migrations are prerequisites already installed for this application. No new provider credentials are needed. Payments remain deferred.

Validation: native PostgreSQL-compatible tests cover private ownership, explicit permissions, read-only users, edits without broad planner permissions, approval cycles, optimistic conflicts, duplicate-safe imports, file access, signature records, recovery/permanent deletion, reminders, administrator boundaries, premium/retired templates and anonymous denial. Mobile/browser tests cover category browsing, reviewed personalization, rich tables/checklists, autosave retry identity, conflict retention, HTML sanitization, admin publication and Word package/PDF rendering. Word package XML is checked for a real table. The automated browser environment cancels filesystem downloads even for a plain text Blob, so export tests validate generated bytes and download initiation directly. Real-device download and account testing remains deferred at the user's request.
